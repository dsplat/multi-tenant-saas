## 一、背景与定位

平台从「提供工具」演进为「供给资源与能力」：租户向平台购买 AI 积分、按需开通付费能力、选入平台分销的内容与积分商城 SKU，再面向自己的用户（User）开展运营。

**与现有系统的关系（现状基线）**：

| 能力 | 现状 | 所在模块 |
|---|---|---|
| 租户积分账户 | 已有：`credit_accounts`（tenant 级账户，`user_id=null`）、充值/批量充值 API、流水、低额通知、过期处理命令 | `src/Modules/Billing/` |
| AI 能力计费 | 已有：`CapabilityBillingService` 按能力计价扣积分、`AiUsageService` 配额预算、租户级能力开关 | `src/Modules/Ai/` |
| 支付订单 | 已有：`PaymentOrder`（order_no/driver/amount/status）、`PayService` + 微信/支付宝/Stripe/PayPal/银联驱动 | `src/Modules/Billing/` |
| 模块开通 | 已有：按套餐差异化开通（`config/tenancy.php → plan_modules`），无独立计价 | `config/tenancy.php` |
| 订阅套餐 | 已有：`SubscriptionPlan` / `SubscriptionService`（free/basic/pro/enterprise） | `src/Modules/Billing/` |
| 委托 OAuth 凭证 | 已有：IdP 支持 standard / legacy / delegated 三种协议模式（蓝眼兔租户已生产使用 delegated） | `src/Modules/Auth/` |
| 用户积分商城 | 下游 scrm 已有：`points_products` + 兑换接口（租户自建 SKU，面向自己的 User） | scrm `app/Modules/Membership/` |

**缺口**：积分「购买」闭环（当前充值为手动/后台发放，无商品化套餐与支付回调自动到账）、模块单独付费开通、平台级内容库与分销、平台级 SKU 库与分销。

## 二、术语与角色

| 术语 | 定义 |
|---|---|
| **AI 积分** | 租户级预付额度，消耗于平台 AI 能力（文本/图像/视频/对话等），存于 `credit_accounts`，平台统一计价 |
| **用户积分** | 租户运营自己的 User 的积分体系（下游 Membership 模块），与 AI 积分是两套账，不混用 |
| **平台商品** | 平台侧维护的可售资源：积分包、模块开通项、内容包、SKU 包 |
| **选入** | 租户从平台商品库挑选资源纳入自己名下经营（产生租户级副本或授权记录） |

**身份约束（铁律）**：购买/开通/选入的操作主体是租户运营人员（Operator，scope=tenant）；兑换/消费内容的受众是租户的用户（User）。不引入 customer 作为独立身份主体；SKU 兑换的业务主体一律用 user_id。

## 三、功能一：租户向平台购买 AI 积分

### 3.1 业务描述

平台定义积分包商品（面额、售价、赠送规则、有效期），租户下单支付后积分自动到账，用于 AI 能力消耗。支持后台手动发放（对公转账等线下场景）。

### 3.2 系统能力要求

| 能力 | 说明 | 复用/新建 |
|---|---|---|
| 积分包商品管理 | 平台侧维护：名称、积分面额、赠送额、售价、上下架、有效期策略 | 新建（平台级表，无 tenant_id） |
| 购买订单闭环 | 下单 → 支付（复用 PayService 驱动）→ 回调验签 → 自动充值到账 → 开票 | 复用 `PaymentOrder` + `PayService`，新建「订单类型=积分购买」与回调发放逻辑 |
| 到账发放 | 支付成功事件驱动 `CreditAccount::recharge`，区分充值额与赠送额（`recharge_balance` / `gift_balance` 字段已存在） | 复用 |
| 消耗记账 | AI 调用按能力计价扣减（`CapabilityBillingService` 已有），流水可追溯 | 复用 |
| 余额预警 | 低于阈值通知租户（阈值 `tenancy.credit_warning_threshold`） | 复用 `CreditLowNotification` |
| 有效期与过期 | 积分包可设有效期，到期清零/结转策略可配 | 复用 `ProcessCreditExpiry` 命令，扩展按批次过期 |
| 线下发放 | 平台后台对指定租户手动/批量发放（对公转账、补偿、活动赠送） | 复用 `batchRecharge` |
| 财务对账 | 订单、流水、发票三方对账；平台侧营收汇总 | 复用 `InvoiceService` + `FinancialRecord` |

### 3.3 待确认

- 支付渠道范围（微信支付/支付宝是否已具备商户资质接入生产）。
- 赠送积分与充值积分的消耗顺序（建议先消耗赠送额）。
- 是否需要积分包阶梯折扣 / 大客户协议价。

## 四、功能二：能力/模块付费开通

### 3.1 业务描述

租户在套餐之外，可对单个能力模块付费开通（加购），或购买能力包（模块组合）。开通即时生效，到期自动回收。

### 3.2 系统能力要求

| 能力 | 说明 | 复用/新建 |
|---|---|---|
| 模块商品化 | 平台为可加购模块定义计价项（现有 32 模块中筛选：payment / ssl / api-token / sms / lottery 等） | 新建（模块商品表：模块标识、计费模式、价格、周期） |
| 计费模式 | 支持：一次性买断 / 按月订阅 / 积分抵扣三选（按模块配置） | 新建；订阅复用 `SubscriptionService`，积分抵扣复用 `CreditAccount` |
| 开通生效 | 支付成功 → 写租户模块开通记录 → 覆盖 `plan_modules` 默认值 | 扩展现有模块开关机制（当前仅套餐驱动，需增加「加购覆盖层」） |
| 到期回收 | 订阅到期未续费 → 模块降级关闭，数据保留 | 新建定时任务（参照 `ProcessSubscriptions`） |
| 与套餐叠加规则 | 套餐已含的模块不重复计费；套餐降级时已加购模块保持独立有效 | 新建规则 |
| AI 能力粒度开通 | AI 子能力（text/image/video）的开通与预算，继续走 `config/ai.php` 租户级开关，可纳入能力包售卖 | 复用 `AiConfigService.isCategoryEnabled` |

### 3.3 待确认

- 主推计费模式（买断 vs 订阅 vs 积分抵扣，可多选但需定默认）。
- 模块开通是否需要平台审核（部分模块如 payment 涉及资质）。

## 五、功能三：平台内容分销

### 5.1 业务描述

平台维护内容库（运营素材、文章、话术、模板等），租户选入后提供给自己的用户使用。

### 5.2 系统能力要求

| 能力 | 说明 | 复用/新建 |
|---|---|---|
| 平台内容库 | 平台侧内容管理：分类、标签、上下架、定价属性（免费/积分/付费） | 新建（平台级内容表 + 内容包表） |
| 租户选入 | 租户从内容库选入，产生租户级授权记录；内容更新同步策略可配（自动同步 / 快照锁定） | 新建 |
| 面向用户分发 | 选入内容经租户前台（H5/内容中心）向 User 展示；租户可控制可见范围与展示开关 | 新建（下游项目承接展示层） |
| 结算模型 | 免费 / AI 积分扣减 / 收益分成，按内容包配置 | 新建结算记录，扣减复用 `CreditAccount` |
| 版权与合规 | 内容来源标注、授权范围（仅展示/可编辑/可再分发）、下架联动（平台下架 → 租户侧同步失效） | 新建 |

### 5.3 待确认

- 内容类型范围（素材/文章/话术/课程/模板，需圈定首批）。
- 选入后是「引用」（平台更新即同步）还是「副本」（租户独立持有）——决定存储模型。
- 展示层归属：框架提供内容分发 API，展示由下游项目（scrm H5）实现。

## 六、功能四：平台积分商城 SKU 分销

### 6.1 业务描述

平台维护积分商城 SKU 库（实物商品、虚拟权益、卡券等），租户选入后，用自己的用户积分体系面向 User 开展兑换。

### 6.2 系统能力要求

| 能力 | 说明 | 复用/新建 |
|---|---|---|
| 平台 SKU 库 | 平台侧 SKU 管理：名称、类型（实物/虚拟/卡券）、供货价、建议兑换积分、库存池、上下架 | 新建（平台级 SKU 表） |
| 租户选入 | 租户选入 SKU → 生成租户级 SKU 副本（含租户自定义兑换积分、上下架状态） | 新建；与下游 `points_products` 结构对齐（选入即写入租户 `points_products`，标记来源=平台） |
| 用户兑换 | User 用租户积分兑换（复用下游 Membership 兑换链路），业务主体为 user_id | 复用 scrm `PointsController` 兑换接口 |
| 库存模型 | 二选一：平台共享库存（多租户共池，先到先得）/ 租户配额库存（选入时分配额度） | 新建 |
| 履约 | 实物：平台代发（一件代发）或租户自履约，按 SKU 配置；虚拟/卡券：自动发放（券码核销复用框架 Coupon 模块） | 新建履约流转 |
| 结算 | 平台与租户按供货价结算（积分扣减 / 账期对账 / 收益分成），结算周期可配 | 新建结算单 |
| 售后 | 售后责任主体按 SKU 配置（平台客服 / 租户客服），退换货联动库存与积分回退 | 新建 |

### 6.3 待确认

- 履约主模型（平台代发 vs 租户自履约，首批 SKU 类型）。
- 库存模型（共享池 vs 配额）。
- 结算周期与方式（月结对账 / 实时积分扣减）。

## 七、功能五（可选）：平台资源赋能与委托凭证

### 7.1 业务描述

租户可（非强制）借助平台资源提升运营：领取/购买资源包（AI 积分 + 内容包 + 新用户福利），并可选择让自有机器人使用平台提供的 OAuth 凭证（code/secret）接入渠道，无需自备资质。

> ⚠️ 原始表述「让机器人使用娃提供的 code 和 secret」存在歧义，本节按「平台提供委托凭证」解读，待第九节确认。

### 7.2 系统能力要求

| 能力 | 说明 | 复用/新建 |
|---|---|---|
| 资源包 | 平台组合资源（积分额度 + 内容包 + 福利券），租户一键领取/购买；新用户福利发放规则可配 | 新建资源包模型，发放复用 Billing/Coupon |
| 委托凭证接入 | 租户机器人使用平台持有的渠道凭证（如微信开放平台 appid/secret）完成授权，平台侧代管凭证、按租户下发授权 | 复用 IdP delegated 协议模式（已生产验证） |
| 凭证范围管控 | 按租户限定委托凭证可用的能力范围与渠道，凭证使用留痕 | 扩展 delegated 授权记录 |
| 审计 | 委托凭证的每次使用可追溯到租户与机器人实例 | 复用 `AuditService` |

### 7.3 待确认

- 「娃」所指：平台 / 某上游合作方 / 某租户？
- 「机器人」所指：微信公众号机器人 / AI 数字员工 / 企微机器人？
- 委托凭证的渠道范围（微信开放平台 / 企业微信 / 其他）。

## 八、非功能约束

| 约束 | 要求 |
|---|---|
| 身份模型 | 仅 Operator / User 两种身份实体；购买主体=租户（Operator 操作），兑换主体=User（user_id）；禁止引入 customer 独立身份 |
| 数据隔离 | 平台商品/内容/SKU 库为平台级（无 tenant_id）；租户选入后的副本/授权记录携带 tenant_id，受 `TenantScope` 隔离 |
| 财务审计 | 一切发放、消耗、结算有流水 + 审计日志（`AuditService`），订单-流水-发票可对账 |
| AI 可选性 | 本体系不依赖 AI 能力运转（AI 仅作为被消费资源），AI 瘫痪不影响购买/兑换主链路 |
| 框架/项目分层 | 积分账户、订单、模块开通、内容/SKU 分销 API 属框架层；用户侧展示与兑换交互由下游项目（scrm）承接，复用框架服务而非自建 |

## 十、优先级建议

| 优先级 | 功能 | 理由 | 状态 |
|---|---|---|---|
| **P0** | AI 积分购买闭环 | 基线最完整（账户/计费/订单/通知齐备），增量最小，商业化价值最直接 | ✅ 已完成（CreditPackFulfillmentHandler） |
| **P1** | 模块付费开通 | 仅需在现有模块开关机制上加「加购覆盖层」+ 商品表 | ✅ 已完成（ModuleFulfillmentHandler + module_entitlements） |
| **P2** | 积分商城 SKU 分销 | 需与下游 Membership 协同，但用户侧兑换链路已存在 | ✅ 已完成（MallSupplyFulfillmentHandler + SupplyProvisionerContract） |
| **P3** | 内容分销 | 需从零建内容库，且展示层依赖下游项目 | ✅ 已完成（ContentPackFulfillmentHandler + PlatformContentLibraryService） |
| **可选** | 资源包 + 委托凭证 | 委托凭证已有 delegated 模式基线，资源包是前述能力的组合封装 | 待定 |
