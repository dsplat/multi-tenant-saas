# AI 流式网关使用手册

## 模块简介

AI 流式网关是为支持实时流式响应而设计的中间层服务，主要解决前端应用在调用 AI 服务时的延迟、连接中断与资源调度问题。该模块通过 Node.js 的 SSE（Server-Sent Events）引擎实现低延迟、高并发的流式数据推送，并由 PHP 契约 API 提供统一的鉴权、配额控制、工具执行与用量统计能力。

该模块可按租户独立开关，适用于需要对 AI 调用进行精细化管理的多租户 SaaS 场景。其核心价值在于：  
- 实现浏览器端与 AI 服务之间的稳定、持续、可监控的流式通信；  
- 在不暴露敏感信息的前提下，完成 API 密钥的安全传递与动态下发；  
- 支持跨系统协作，确保每个请求的使用行为可追踪、可结算。

## 核心功能

### 流式对话解析（resolve）

当用户发起一次流式对话请求时，前端将请求发送至配置的公开路径（如 `/ai-stream/chat`），由 Nginx 反代至 Node 引擎。Node 引擎会调用 PHP 后端的 `resolve` 接口，获取 AI 服务的上游地址、认证方式及初始参数，从而建立真正的流式连接。

此过程实现了“前端请求 → 网关解析 → 上游对接”的完整链路，保障了连接的可靠性与安全性。

### 工具调用执行（tools/execute）

在对话过程中，若需调用外部工具（如数据库查询、文件生成等），Node 引擎将向 PHP 后端的 `tools/execute` 接口发起请求。该接口负责验证当前租户是否有权限调用指定工具，并根据配置决定是否允许执行。

该功能支持动态控制工具访问权限，防止未授权操作，同时为后续的计费与审计提供依据。

### 使用量上报（usage/report）

每次流式会话结束后，Node 引擎会主动向 PHP 后端的 `usage/report` 接口提交本次调用的使用明细，包括但不限于：  
- 请求时间范围  
- 数据传输量（字节数）  
- 所用工具数量与类型  
- 是否成功完成流式响应  

这些数据用于租户级别的用量统计、账单生成与资源配额管理。

## 常见操作流程

### 1. 启用或禁用模块（租户级）

管理员可通过系统配置界面开启或关闭该模块。  
- 当前状态由 `ai-streaming.enabled` 配置项控制。  
- 若设置为 `false`，所有契约 API 将返回 503 错误，导致流式请求无法正常处理。  
- 开启后，Node 引擎可正常接收并处理来自前端的请求。

> 注：该开关影响整个租户的 AI 流式能力，建议在维护窗口期调整。

### 2. 配置公开访问路径

前端客户端需通过配置的公开路径发起请求，例如：  
```
POST /ai-stream/chat
```

该路径由 `ai-streaming.public_path` 配置项定义，默认值为 `/ai-stream`。  
Nginx 需正确配置反代规则，将该路径指向本地运行的 Node 引擎（监听于 `127.0.0.1:9200`）。

### 3. 处理流式请求生命周期

1. 用户在前端发起流式对话请求，携带有效的 `Authorization: Bearer <token>`；
2. 请求经由 Nginx 反代至 Node 引擎；
3. Node 引擎调用 PHP 的 `/ai-streaming/resolve` 接口，获取上游服务配置；
4. 成功获取配置后，建立与上游 AI 服务的流式连接；
5. 若涉及工具调用，节点调用 `/ai-streaming/tools/execute` 进行权限校验；
6. 对话结束时，节点调用 `/ai-streaming/usage/report` 上报使用详情。

整个流程中，所有关键环节均由 PHP 契约 API 控制，确保安全可控。

### 4. 查看使用记录与用量统计

系统后台可通过 `usage/report` 接口收集的数据，生成各租户的使用报表。  
- 报表内容包含：请求次数、总流量、工具调用频次、失败率等；  
- 可用于分析资源消耗趋势、识别异常行为、制定计费策略。

## 相关配置说明

### 模块总开关（enabled）

- 类型：布尔值（true/false）
- 默认值：`true`
- 作用：全局控制模块是否可用。
- 影响：关闭时，所有契约 API 返回 503，拒绝服务。

### Node 引擎监听地址（node.host & node.port）

- `host`：Node 引擎绑定的本地 IP 地址，默认为 `127.0.0.1`，仅限内网访问。
- `port`：监听端口，默认为 `9200`。
- 安全提示：该地址不应暴露于公网，必须通过 Nginx 反代访问。

### 公开访问路径（public_path）

- 定义前端请求入口路径，如 `/ai-stream/chat`。
- 必须与 Nginx 配置中的 `location` 一致。
- 建议保持默认值，避免因路径变更导致前端请求失败。

### PHP 契约 API 回调基址（php_api_base）

- Node 引擎回调 PHP 的基础 URL，如 `http://127.0.0.1/api/v1`。
- 推荐同机部署，走回环地址以减少网络延迟与风险。
- 不应指向公网地址，除非明确有跨机房需求。

### API Key 下发策略（api_key_strategy）

- 可选值：`direct` 或 `none`
- `direct`：在 resolve 响应中直接返回 provider API key，适用于内网环境；
- `none`：不下发 key，要求 Node 侧自行通过环境变量配置密钥。

> 选择建议：若 Node 与 PHP 同机部署且网络隔离，则推荐使用 `direct`；否则应使用 `none` 并提前配置环境变量。
