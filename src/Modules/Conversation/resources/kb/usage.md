# 会话中心使用手册

## 模块简介

会话中心是多渠道统一会话管理的核心模块，支持跨渠道（如客服、社交媒体、邮件等）的会话聚合与路由。该模块帮助运营人员集中管理客户沟通记录，实现消息的高效流转、参与者协作、状态追踪与内容沉淀。

主要解决以下业务问题：
- 多渠道客户消息分散，难以统一查看与跟进；
- 会话中关键信息遗漏，缺乏摘要与归档机制；
- 参与者变动后无法及时同步消息权限；
- 消息未读状态不清晰，影响响应效率；
- 重要提及（@）信息容易被忽略；
- 会话标签缺失，导致后续检索困难。

通过本模块，运营人员可完成会话创建、成员管理、消息发送与撤回、已读状态跟踪、智能摘要生成、标签分类及历史消息查询等操作，全面提升客户服务效率与质量。

## 核心功能

### 会话创建与管理

支持为特定租户创建新会话，可指定会话类型（如“客服对话”、“工单”、“群聊”），并添加初始参与者。会话创建后自动记录创建时间、最后消息时间、总消息数等元数据。

- **创建会话**：通过接口发起请求，传入会话类型和参与者列表，系统将生成唯一会话标识，并初始化相关元信息。
- **删除会话**：执行软删除操作，将会话标记为已归档（archived），保留历史数据但不再显示在默认列表中。
- **获取会话详情**：根据会话 ID 查询其完整信息，包括标题、频道、状态、参与人、摘要等。

### 消息收发与处理

支持在会话内发送、查看、搜索和撤回消息，确保沟通过程可控且可追溯。

- **发送消息**：向指定会话发送文本或结构化消息，系统自动记录发送者、时间戳与消息类型。
- **撤回消息**：在消息发出后的30分钟内可撤回，撤回后原消息仍保留在系统中，仅对用户不可见。
- **搜索消息**：基于关键词、时间范围、发送者等条件检索历史消息，便于快速定位信息。
- **获取消息列表**：分页拉取会话内所有消息，支持按时间倒序排列。

### 参与者与权限管理

支持动态增减会话中的参与者，调整角色与权限，保障沟通安全。

- **添加/移除参与者**：可在会话创建后随时添加新成员或移除已有成员，系统自动更新参与人列表。
- **查看参与者列表**：实时获取当前会话的所有成员及其加入时间、最后阅读时间等状态。

### 已读状态与未读提醒

系统自动维护每个用户在各会话中的已读状态，支持精准推送未读提醒。

- **标记已读**：当用户查看会话时，系统自动更新其最后已读消息 ID 与未读计数。
- **获取未读数量**：可查询某用户在所有会话中的未读消息总数，用于监控响应延迟。
- **重置未读状态**：在会话归档或清理时，可一键清空所有参与者的未读计数。

### 智能摘要生成

系统可自动生成会话摘要，提炼核心要点，提升信息复用效率。

- **生成摘要**：基于会话内的消息内容、参与者、关键点等信息，自动生成结构化摘要。
- **更新摘要**：当会话有新消息或变更时，系统可重新计算并更新摘要内容。
- **获取摘要**：查看当前会话的摘要信息，包含参与者概览、重点事件、消息总量等。

### 提及功能（@通知）

支持在消息中 @ 用户，触发提醒机制，确保关键人物及时响应。

- **解析提及**：系统自动识别消息中的 `@<用户ID>` 形式，创建提及记录。
- **获取提及列表**：查看某条消息中被提及的用户，或某用户被提及的所有记录。
- **标记已通知**：将未通知的提及标记为已通知，避免重复提醒。

### 标签管理

支持为会话添加标签，便于后续分类、筛选与统计分析。

- **添加/移除标签**：为会话打上标签（如“紧急”、“待跟进”、“投诉”），支持批量同步。
- **按标签检索会话**：通过标签快速查找相关会话，提高工作效率。
- **同步标签集合**：使会话的标签列表与指定列表完全一致，防止冗余或缺失。

### 会话连接与活跃度管理

支持会话级连接状态管理，用于监控在线会话与用户活跃情况。

- **连接会话**：建立用户与会话之间的连接通道，用于接收实时消息。
- **断开连接**：主动关闭某个用户的会话连接。
- **心跳更新**：定期上报活跃时间，保持连接有效性。
- **清理空闲连接**：系统自动识别长时间无操作的连接并标记为闲置，释放资源。

### 时间线与消息流

提供会话的时间轴视图，展示消息按时间顺序的完整流动过程。

- **获取时间线**：以时间线形式展示会话内所有消息，支持滚动加载与分页。
- **标记时间线已读**：在时间线视图中，可一键标记全部消息为已读。

## 常见操作流程

### 创建一个新会话
1. 确定会话类型（如“客户咨询”、“内部协作”）；
2. 准备需要加入会话的用户 ID 列表；
3. 调用 `/tenant/conversations` 接口，提交 `type` 和 `participant_ids` 参数；
4. 系统返回新创建的会话 ID 与基本信息，可用于后续操作。

### 向会话发送消息
1. 获取目标会话 ID；
2. 调用消息发送接口，传入 `conversation_id`、`sender_id`、`content` 等字段；
3. 消息立即进入会话消息流，其他参与者可见。

### 添加新成员到会话
1. 确定要添加的用户 ID；
2. 调用 `addParticipant()` 接口，传入会话 ID 与用户 ID；
3. 成功后，该用户将获得会话访问权限，并开始接收新消息。

### 查找包含特定标签的会话
1. 在系统中输入目标标签（如“高优先级”）；
2. 使用 `findConversationsByTag()` 接口查询所有匹配的会话；
3. 展示结果列表，可进一步查看详情或进行处理。

### 生成并查看会话摘要
1. 会话持续产生消息后，系统自动触发摘要生成；
2. 调用 `getSummary()` 接口获取当前摘要内容；
3. 查看摘要中的关键点、参与者、消息总数等信息，辅助快速理解会话背景。

### 处理未读消息提醒
1. 运营人员登录系统后，系统自动加载其所有会话的未读状态；
2. 若发现未读消息，可点击进入对应会话；
3. 阅读后，系统自动更新已读状态与未读计数。

### 撤回误发消息
1. 发现已发送的消息存在错误或敏感内容；
2. 在消息发出后30分钟内，调用 `revokeMessage()` 接口，传入消息 ID；
3. 消息从用户界面移除，但原始数据仍保留在系统中。

## 相关配置说明

本模块不提供独立的前端控制台菜单路径，所有功能通过 API 接口暴露，需由集成系统或管理后台调用。

- **会话类型（type）**：由系统预定义，具体值由业务上下文决定，如“chat”、“ticket”、“group”等；
- **消息撤回时限**：系统限制为消息发出后30分钟内可撤回，超时则无法操作；
- **标签同步策略**：`syncTags()` 接口会覆盖原有标签，确保与目标列表一致；
- **提及通知机制**：系统默认未通知状态，需手动或通过定时任务触发 `markNotified()`；
- **摘要生成时机**：系统在会话更新后自动触发，也可手动调用 `generateSummary()`；
- **连接超时设置**：空闲连接的判定依赖于 `idleMinutes` 配置项，具体数值由系统管理员设定，但不在本模块文档中体现。

> 注：所有配置项均通过系统级参数或环境变量管理，无需运营人员直接干预。
