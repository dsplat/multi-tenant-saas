# 开发者门户使用手册

## 模块简介

开发者门户模块为注册的开发者提供 API 文档查阅、沙箱环境测试及 SDK 管理支持。通过该模块，开发者可在线查看完整的 API 接口文档，快速创建独立的沙箱环境进行接口调试与集成测试，并获取专属的测试 API Key 用于模拟调用。

本模块主要解决以下问题：
- 开发者缺乏安全、隔离的测试环境，影响开发效率；
- API 文档分散或难以查找，增加接入成本；
- 缺少对测试密钥的统一管理机制。

模块核心能力围绕“文档访问”、“沙箱环境管理”和“测试密钥生成”展开，确保开发者在正式接入前完成充分验证。

---

## 核心功能

### 1. API 文档查阅

开发者可通过门户访问系统提供的完整 API 文档，包括所有公开接口的说明、请求格式、响应示例与错误码解释。

- 支持按分类浏览文档内容；
- 提供文档目录结构，便于快速定位所需接口；
- 文档内容动态加载，无需下载或安装额外工具。

### 2. 沙箱环境管理

沙箱环境是为每个开发者提供的独立测试空间，用于模拟真实业务场景下的 API 调用行为，避免对生产数据造成影响。

- 可创建一个专属沙箱环境，拥有独立的租户上下文；
- 支持在沙箱中生成测试 API Key 并进行接口调用；
- 沙箱环境与主租户完全隔离，数据不互通；
- 支持自动清理过期沙箱，保障资源安全。

### 3. 测试 API Key 生成与管理

为沙箱环境提供专用的测试密钥，用于身份认证与权限控制。

- 自动为沙箱环境生成以 `sbx_` 为前缀的唯一测试 API Key；
- 支持在沙箱环境中直接获取当前可用的测试密钥；
- 支持查看、更新或吊销已生成的 API Key（仅限于沙箱上下文）；
- 所有测试密钥均绑定特定沙箱环境，不可跨环境使用。

## 常见操作流程

### 创建沙箱环境

1. 进入开发者门户，进入沙箱管理区域；
2. 点击“创建沙箱”按钮；
3. 系统将自动为当前开发者创建一个独立的沙箱租户；
4. 创建完成后，系统返回沙箱环境信息，包括测试 API Key 和访问地址；
5. 可立即使用该测试密钥在沙箱环境中调用 API 接口进行测试。

> 注：此操作由后端服务 `SandboxService::createSandbox()` 实现，调用路径为 `/tenant/developer/sandbox`。

### 查看当前沙箱环境

1. 在开发者门户中进入“沙箱状态”页面；
2. 系统自动查询并展示当前租户关联的沙箱环境信息；
3. 显示内容包括：沙箱 ID、创建时间、状态（活跃/已清理）、测试 API Key 等；
4. 若未创建沙箱，则提示“暂无沙箱环境”。

> 注：此功能通过 `SandboxService::getTenantSandbox()` 实现，调用路径为 `/tenant/developer/sandbox`。

### 获取 API 文档

1. 在开发者门户中点击“API 文档”入口；
2. 系统返回文档目录列表，包含多个分类（如账户管理、支付接口、订单处理等）；
3. 选择某一分类，系统加载对应文档内容；
4. 可逐页查看接口说明、请求参数、响应样例等信息。

> 注：文档数据通过 `DeveloperPortalService::getDocumentationCategories()` 和 `getDocumentationByCategory()` 提供，调用路径为 `/tenant/developer/docs`。

### 清理沙箱环境

1. 在沙箱管理界面，确认需删除的沙箱环境；
2. 执行“清理”操作；
3. 系统将执行删除沙箱租户及关联记录的操作；
4. 操作完成后，该沙箱环境不再可用。

> 注：此功能由 `SandboxService::cleanup()` 实现，支持手动触发；同时系统支持定时任务自动清理过期沙箱。

## 相关配置说明

本模块不提供可配置项供运营人员调整。所有行为由系统默认逻辑控制：

- 沙箱环境的创建与清理由后台服务自动管理；
- 测试 API Key 的生成规则固定为 `sbx_` + 64 位随机字符串；
- 沙箱环境的有效期由调度任务自动判断并清理；
- 所有接口调用均基于当前登录开发者身份，权限受租户上下文限制。

> 注：模块本身不可开关，且无前端菜单路径暴露，所有功能通过后端接口驱动，运营人员无需进行任何配置操作。
