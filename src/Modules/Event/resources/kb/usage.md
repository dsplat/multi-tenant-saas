# 事件总线使用手册

## 模块简介

事件总线模块用于实现系统内各组件之间的异步事件分发与外部系统对接。通过该模块，系统可将关键业务事件（如AI视频生成完成、系统公告发布等）以标准化方式广播至内部实时通道或外部订阅系统，支持租户级隔离和安全的Webhook投递机制。本模块主要解决跨服务通信延迟高、外部系统无法及时感知系统状态变化的问题，确保重要事件能被可靠传递。

## 核心功能

### 实时广播通知

系统可通过事件总线向指定租户或用户实时推送消息。所有广播事件均基于频道进行路由，支持以下场景：

- **租户级广播**：向整个租户范围内的客户端推送事件，适用于全局性变更通知。
- **用户级广播**：定向发送至特定用户的客户端，用于个性化提醒或状态更新。
- **系统公告推送**：管理员可触发系统公告，实时推送到所有在线用户终端。
- **AI视频生成完成通知**：当AI视频处理任务完成后，自动广播结果，供前端展示或后续流程调用。
- **在线状态同步**：用户登录/登出时，系统会自动广播其在线状态，保持多端状态一致。

### 外部事件订阅与Webhook投递

支持外部系统通过注册订阅接收特定类型的事件。一旦事件发生，系统将按配置向指定地址发起HTTP请求（Webhook），实现与第三方系统的联动。

- 订阅类型包括但不限于：事件类型匹配、租户范围匹配。
- 支持为每个订阅设置独立密钥（secret），用于验证请求来源合法性。
- 所有订阅均可启用或禁用，便于灵活控制事件流向。

### 广播事件历史查询

运营人员可通过接口获取当前租户下最近发生的广播事件记录，用于排查问题或审计事件流转情况。数据按租户维度隔离，确保信息安全性。

### 事件重试机制

对于因网络异常等原因未能成功投递的广播事件，系统提供重试能力，可主动触发未完成事件的再次投递，保障事件最终送达。

## 常见操作流程

### 1. 查看近期事件日志

运营人员可通过访问以下接口查看当前租户最近100条广播事件：

```
GET /tenant/events
```

返回内容包含事件ID、事件类型、目标频道、载荷内容、是否已发送、失败原因及发送时间等字段，可用于快速定位异常事件。

> 注：该接口仅对当前租户可见，数据受租户作用域自动隔离。

### 2. 启用或禁用外部事件订阅

若需对外部系统开放某类事件的订阅，可在管理后台（如有）中操作如下：

- 进入事件订阅管理界面；
- 创建新订阅，填写事件类型、目标URL、回调密钥（secret）；
- 设置订阅状态为“启用”；
- 保存后，系统将在对应事件触发时自动向该URL发起POST请求。

### 3. 触发系统公告实时推送

当需要向所有在线用户发布系统通知时，执行以下步骤：

- 调用 `broadcastSystemAnnouncement()` 方法；
- 提供公告内容与目标租户；
- 系统将自动将消息广播至所有相关用户频道；
- 客户端可即时接收并展示公告。

### 4. 重试未发送的广播事件

若发现部分广播事件长期处于未发送状态，可执行重试操作：

- 通过接口调用 `retryPending()` 方法；
- 系统将扫描所有待发送的广播事件，并尝试重新投递；
- 成功后更新事件状态为“已发送”。

## 相关配置说明

- **广播驱动配置**：系统依赖于已配置的广播驱动（如Redis、Database等），若未正确配置，`isAvailable()` 将返回 false，导致广播功能不可用。
- **事件订阅状态控制**：每个订阅项均有 `is_active` 字段，决定是否生效。关闭后，即使事件触发也不会投递。
- **事件类型定义**：所有事件类型由系统预设，外部订阅需根据实际可用类型进行选择。
- **安全校验机制**：Webhook请求携带签名（基于secret生成），外部系统需验证签名有效性以防止伪造请求。

> 本模块不提供配额限制、次数上限、有效期设置等数值型配置项，具体行为由系统运行环境决定。
