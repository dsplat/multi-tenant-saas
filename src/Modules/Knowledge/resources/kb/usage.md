# 知识库使用手册

## 模块简介

知识库模块用于管理租户与外部知识库系统的连接，支持对接 Dify、RAGFlow、FastGPT 等主流 RAG 平台。通过该模块，运营人员可为租户配置专属的知识库连接，实现文档检索、内容同步等能力，并在租户未配置时自动回退至平台默认设置，保障服务可用性。

本模块主要解决以下问题：
- 多租户环境下对外部知识库的差异化接入需求；
- 避免因租户配置缺失导致知识检索失败；
- 提供统一入口管理不同知识库系统的连接状态与配置。

## 核心功能

### 1. 租户级外部知识库连接管理

运营人员可在控制台对每个租户配置独立的外部知识库连接。支持添加、编辑、删除连接，以及测试连接有效性。

- **创建连接**：填写连接名称、选择提供商类型（如 Dify、RAGFlow）、输入 API 地址与密钥，保存后即生效。
- **编辑连接**：修改连接名称、API 地址或配置参数，支持仅更新部分字段。
- **删除连接**：移除不再使用的连接，系统将自动切换至平台默认配置（若启用）。
- **测试连接**：验证当前配置是否能正常访问目标知识库服务，返回健康状态信息。

> 注：所有连接均绑定于特定租户，确保数据隔离。

### 2. 多源知识库检索能力

系统支持从多个外部知识库中检索内容，优先使用租户配置的连接，若租户无有效连接，则自动回退至平台默认配置。

- 支持调用 Dify、RAGFlow、FastGPT、阿里云百炼等平台的检索接口；
- 检索过程自动完成连接选择与状态判断，无需人工干预；
- 检索结果由各 Provider 原生返回，格式与语义保持一致。

### 3. 文档推送与同步

支持将本地文本文档主动推送到指定租户的外部知识库中，实现内容同步。

- **Dify**：以文本形式上传，系统自动分段处理；
- **FastGPT**：作为文本集合上传，系统自动分块并触发训练；
- **RAGFlow**：将文本封装为 .txt 文件附件上传，随后触发解析流程；
- **阿里云百炼**：直接推送至指定知识库。

> 推送操作不依赖用户交互，可集成至自动化流程中。

### 4. 连接状态与配置展示

系统提供清晰的状态标识，帮助运营人员快速识别当前使用的是租户连接还是平台默认配置。

- `resolveStatus()` 方法返回当前生效的连接来源；
- 控制台界面显示“使用租户配置”或“使用平台默认”状态；
- 所有敏感信息（如 API 密钥）在展示时已脱敏处理。

## 常见操作流程

### 流程一：为租户配置外部知识库连接

1. 进入租户设置页面（路径：`/tenant/external-kb/connections`）；
2. 点击“新增连接”按钮；
3. 填写连接基本信息：
   - 名称（如“客户合同知识库”）；
   - 选择提供商类型（Dify / RAGFlow / FastGPT / 百炼）；
   - 输入 API 地址（如 `https://api.dify.ai/v1/knowledge_bases`）；
   - 输入 API 密钥（系统自动加密存储）；
   - 可选：填写额外配置参数（如模型 ID、索引名等，具体取决于提供商）；
4. 点击“保存”；
5. 立即点击“测试连接”按钮，确认连接可达；
6. 若测试成功，该连接将立即生效，后续检索将优先使用此配置。

### 流程二：推送文本文档至外部知识库

1. 准备待推送的文本文档（纯文本格式）；
2. 在租户外部知识库连接列表中，选择目标连接；
3. 点击“推送文档”按钮；
4. 上传文件或粘贴文本内容；
5. 系统根据所选提供商类型执行对应逻辑：
   - Dify：自动分段并创建知识条目；
   - FastGPT：作为文本集合上传并触发训练；
   - RAGFlow：生成 .txt 附件并提交至解析队列；
   - 百炼：直接推送至指定知识库；
6. 操作完成后，系统记录 `last_synced_at` 时间戳，表示同步完成。

### 流程三：切换或恢复平台默认配置

1. 若租户连接失效或被删除，系统将自动检测并切换至平台默认配置；
2. 运营人员可通过 `getPlatformDefault()` 查询平台默认配置是否存在；
3. 若需强制启用平台默认，可手动删除租户连接，系统将自动回退；
4. 当租户重新配置有效连接后，系统将恢复使用租户配置。

## 相关配置说明

### 数据表结构说明

- **external_kb_connections** 表存储所有租户的外部知识库连接信息：
  - `tenant_id`：所属租户唯一标识；
  - `provider_type`：连接类型（如 `dify`, `ragflow`, `fastgpt`, `bailian`）；
  - `name`：连接自定义名称；
  - `api_url`：目标服务的 API 入口地址；
  - `api_key_encrypted`：加密后的 API 密钥，不可明文查看；
  - `status`：连接状态（如 `active`, `inactive`）；
  - `last_synced_at`：最近一次文档推送时间；
  - `config`：JSON 格式附加配置（如索引名、模型参数等）；
  - `metadata`：扩展元数据字段（可用于标记用途或来源）；
  - `created_at` / `updated_at`：创建与更新时间；
  - `deleted_at`：软删除时间戳。

> 所有连接均支持软删除，历史数据保留以便审计。

### 配置优先级规则

系统在执行检索或推送操作时，按以下顺序确定使用哪个配置：

1. 优先使用当前租户的有效连接（`status = active`）；
2. 若租户无有效连接，则使用平台默认配置；
3. 若平台默认配置也不存在或未启用，则操作失败。

> 此机制确保服务连续性，避免因配置缺失导致功能中断。

### 安全与权限控制

- 所有连接操作受 RBAC 权限控制：
  - 查看连接：需具备 `setting.view` 权限；
  - 修改或删除连接：需具备 `setting.update` 权限；
- API 密钥在数据库中加密存储，传输过程中采用安全协议；
- 所有连接信息仅限授权人员访问，禁止越权查看。
