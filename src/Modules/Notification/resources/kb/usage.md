# 通知中心使用手册

## 模块简介

通知中心模块用于管理用户在系统内的站内通知，支持通知的创建、查看、标记已读、删除及偏好设置。该模块帮助运营人员向用户发送重要信息（如账户状态变更、订阅提醒、支付成功等），并允许用户按需控制接收渠道与类型，提升信息触达效率与用户体验。

本模块主要解决以下问题：
- 用户无法及时获取关键系统消息；
- 通知内容杂乱，缺乏分类与优先级管理；
- 用户对通知接收方式无自主控制权；
- 运营无法批量或定向推送通知。

通过统一的通知入口与灵活的偏好配置，确保重要信息有效传达，同时避免信息过载。

## 核心功能

### 站内通知管理

可对用户的站内通知进行全生命周期管理，包括查看、标记已读、删除和清空已读记录。

- **查看通知列表**：获取当前用户所有站内通知，支持分页展示。
- **标记为已读**：可单独或批量将通知标记为已读状态，更新未读计数。
- **删除通知**：支持删除单条通知（软删除，保留数据用于审计）。
- **清空已读通知**：一键清除所有已读状态的通知记录，释放存储空间并保持界面整洁。

> 注：操作均基于当前登录用户身份，仅可操作归属自身的通知。

### 通知偏好设置

用户可根据自身需求，自定义不同通知类型的接收方式与开关状态。

- **查看偏好设置**：获取当前用户已配置的通知偏好。
- **修改偏好设置**：针对特定通知类型（如“订阅即将过期”、“支付成功”等），开启或关闭接收。
- **批量更新偏好**：支持一次性调整多个通知类别的接收状态，适用于统一策略配置。

> 偏好设置影响通知是否被触发，但不影响通知内容本身。

### 通知分类与统计

系统支持按通知类型进行分类管理，并提供未读数量统计能力。

- **获取未读通知总数**：实时查询当前用户未读通知的数量。
- **按类型统计未读数**：可获取各类通知（如系统公告、财务提醒、账户安全等）的未读数量，辅助运营分析重点信息覆盖情况。
- **通知分类列表**：获取系统支持的所有通知类型，用于前端展示或配置参考。

## 常见操作流程

### 1. 向用户发送站内通知

1. 调用 `NotificationService::sendToUser()` 接口，传入目标用户 ID 及通知内容（标题、正文、链接、类型等）。
2. 系统自动创建一条站内通知记录，关联用户与租户。
3. 用户在通知中心可见该条消息，状态为“未读”。

> 示例场景：用户完成支付后，系统自动发送“支付成功”通知。

### 2. 批量发送通知给租户成员

1. 使用 `NotificationService::sendToTenantUsers()` 接口。
2. 指定租户 ID 与通知内容。
3. 系统将向该租户下所有成员发送相同通知，每条记录绑定对应用户。

> 适用场景：发布全员公告、系统维护通知。

### 3. 配置通知偏好（面向用户）

1. 进入通知中心页面（通过控制台菜单路径访问）。
2. 查看当前通知偏好设置列表。
3. 根据需要开启或关闭某类通知的接收权限。
4. 提交更改，系统保存新配置。

> 用户可随时调整偏好，影响后续通知是否送达。

### 4. 清理已读通知记录

1. 在通知中心界面点击“清空已读”按钮。
2. 系统执行 `DELETE /notifications/read/clear` 请求。
3. 所有已读状态的通知记录被移除，但未读通知不受影响。

> 适用于定期清理历史数据，优化性能。

## 相关配置说明

### 通知模板管理（邮件模板）

系统内置邮件模板服务，支持动态渲染通知邮件内容。

- **模板作用域**：每个模板属于特定租户或全局系统范围（tenant_id = null）。
- **模板查找机制**：按三级优先级查找——租户自定义 > 租户默认 > 系统默认。
- **变量替换**：支持使用 `{{variable}}` 语法，在发送时从数据对象中提取值进行填充。
- **模板状态**：可启用或停用模板，停用后不再触发相关通知。

> 模板可通过控制台页面 `Mail Templates` 进行管理与编辑。

### 数据表结构说明

| 表名 | 主要用途 |
|------|--------|
| `in_app_notification` | 存储站内通知核心信息，包括标题、内容、链接、类型、是否已读等字段。 |
| `mail_template` | 存储邮件通知模板，包含主题、HTML/文本正文、语言、变量定义及状态。 |
| `notification_preference` | 记录用户对各类通知的接收偏好，包括通道（如站内、邮件）、类型、是否启用、附加选项。 |

> 所有数据均受租户隔离机制保护，跨租户不可见。
