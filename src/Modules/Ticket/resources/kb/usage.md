# 工单管理模块使用手册

## 模块简介

工单管理模块用于统一处理用户提交的服务请求或问题反馈。通过该模块，运营人员可创建、查看、分配、处理和关闭各类工单，确保问题得到及时响应与闭环管理。本模块适用于客服支持、技术支持、客户反馈等场景，帮助团队高效追踪问题进展，提升服务响应质量。

## 核心功能

### 创建与查看工单

运营人员可在系统中为用户创建新的工单，记录问题的标题、详细描述、优先级及所属类别。所有工单将按状态（如待处理、已分配、已解决）进行分类展示，便于快速定位和跟进。

- 通过 `POST /tickets` 接口创建新工单。
- 工单信息包括：主题（subject）、描述（description）、状态（status）、优先级（priority）、类别（category）等字段。
- 通过 `GET /tickets` 获取当前租户下的所有工单列表。
- 通过 `GET /tickets/{ticketId}` 查看指定工单的完整详情。

### 分配与处理工单

运营人员可将工单指派给具体负责人，确保责任到人。在处理过程中，可根据实际情况更新工单状态，推动问题解决。

- 使用 `POST /tickets/{ticketId}/assign` 接口将工单分配给指定人员（assigned_to 字段）。
- 通过 `PUT /tickets/{ticketId}` 更新工单内容或状态。
- 调用 `POST /tickets/{ticketId}/resolve` 标记工单为已解决状态，完成问题闭环。

### 留言与评论

支持在工单下添加多条评论，实现多方协作沟通。评论内容可由运营人员或用户提交，形成完整的沟通记录。

- 通过 `GET /tickets/{ticketId}/comments` 获取该工单的所有评论列表。
- 使用 `POST /tickets/{ticketId}/comments` 添加新评论，内容由 content 字段承载。

### 删除工单

对于无效或误创建的工单，运营人员可通过删除操作将其移除。删除后，相关数据将不再显示于列表中。

- 通过 `DELETE /tickets/{ticketId}` 删除指定工单。

## 常见操作流程

### 新建工单流程

1. 进入工单管理界面（若存在前端路由）；
2. 点击“新建工单”按钮；
3. 填写工单主题、详细描述、选择优先级与类别；
4. 提交表单，系统自动生成唯一工单编号并保存；
5. 工单进入待分配状态，等待后续指派。

### 分配工单流程

1. 在工单列表中找到需处理的工单；
2. 点击“分配”操作按钮；
3. 从人员列表中选择合适的处理人；
4. 提交分配请求，系统更新 assigned_to 字段；
5. 被分配人员将收到通知，开始处理。

### 处理工单并关闭流程

1. 打开已分配的工单详情页；
2. 查看历史评论与问题背景；
3. 在工单处理过程中，可随时添加评论以记录进展；
4. 当问题解决后，点击“标记为已解决”按钮；
5. 系统将更新 status 为已解决状态，并冻结后续修改。

### 回复用户评论流程

1. 进入目标工单的评论区；
2. 在评论输入框中撰写回复内容；
3. 提交评论，内容将作为新留言显示在工单对话流中；
4. 用户或其他处理人可继续回复，形成完整沟通链路。

## 相关配置说明

本模块不提供独立配置项，其行为完全依赖于系统默认逻辑与数据模型定义。以下字段为关键业务字段，不可随意更改：

- **Ticket** 模型字段：
  - `subject`：工单主题，必填。
  - `description`：问题详细描述，必填。
  - `status`：当前工单状态（如待处理、已分配、已解决）。
  - `priority`：问题优先级（如高、中、低）。
  - `category`：问题所属类别（如账户问题、支付异常、功能咨询）。
  - `assigned_to`：当前负责处理该工单的人员标识。

- **TicketComment** 模型字段：
  - `content`：评论内容，必填。

所有操作均通过标准 API 接口完成，前端页面若存在，应基于上述路由路径进行集成。
