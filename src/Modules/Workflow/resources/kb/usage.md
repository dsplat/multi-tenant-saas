# 工作流引擎使用手册

## 模块简介

工作流引擎用于实现业务流程的自动化编排，支持流程定义、节点执行、条件分支判断、并行任务处理等功能。通过该模块，运营人员可灵活配置复杂业务流程，如审批流、订单处理链路、数据同步任务等，提升跨系统协作效率与流程透明度。本模块适用于需要标准化、可复用、可追踪的业务流程管理场景。

## 核心功能

### 流程创建与管理

支持在租户范围内创建、更新和删除工作流。每个工作流包含名称、描述、版本信息及启用状态，可基于 JSON 格式定义流程结构。通过接口可完成全生命周期管理，确保流程配置清晰可控。

- 创建新流程：提供名称与流程定义（JSON 格式）进行提交。
- 更新现有流程：修改流程名称或重新定义流程逻辑。
- 删除流程：移除不再使用的流程定义，不影响已执行的历史记录。

### 流程执行与调度

支持启动指定工作流的执行实例，传入初始上下文数据以驱动流程运行。系统将根据流程定义自动推进各节点，支持以下执行模式：

- **条件分支**：依据预设条件表达式判断下一步走向。
- **并行处理**：多个子流程同时执行，等待全部完成后再继续。
- **延迟节点**：设置时间延迟后触发后续操作。
- **确认节点**：需人工确认后方可继续执行。
- **动作节点**：执行具体业务操作，如调用外部服务、写入数据库等。

### 执行状态监控与回滚

流程执行过程中可实时查询其状态（如运行中、成功、失败），并支持异常情况下的流程回滚。系统提供以下能力：

- 回滚机制：当流程执行失败时，可按预设规则回退至前序节点，恢复部分或全部执行状态。
- 事务性保障：关键节点执行结果会被记录，确保回滚过程可追溯、可验证。
- 错误日志记录：执行失败时保存错误详情，便于排查问题。

### 流程定义校验与解析

所有流程定义在创建或更新前均经过严格校验，确保结构合法、语法正确。系统支持：

- JSON Schema 校验：检查流程定义是否符合标准格式。
- 详细错误提示：提供具体的校验失败原因，帮助快速修正。
- 定义解析：将流程定义转换为可执行的内部结构，支持动态加载与执行。

## 常见操作流程

### 创建一个新工作流

1. 准备流程定义文件，包含流程名称、节点列表、节点类型、流转逻辑等信息。
2. 调用 `/admin/workflows` 接口，发送 POST 请求，携带 `name` 和 `definition` 字段。
3. 系统返回创建成功响应，包含新流程的 ID 及完整信息。
4. 保存流程 ID 以便后续执行或更新。

### 启动工作流执行实例

1. 确定要执行的工作流 ID。
2. 调用 `/tenant/workflows/{id}/execute` 接口，发送 POST 请求。
3. 在请求体中传入初始上下文数据（context），作为流程运行时的输入参数。
4. 系统返回执行结果，包括当前执行状态与初始节点信息。
5. 可通过查询 `/tenant/workflows/{id}` 获取当前执行实例的最新状态。

### 查看流程执行历史

1. 使用 `/tenant/workflows` 接口获取当前租户下所有已定义的工作流列表。
2. 选择目标流程，调用 `/tenant/workflows/{id}` 获取该流程的详细定义。
3. 查询 `WorkflowExecution` 表中对应记录，查看历史执行实例的状态、开始时间、结束时间及错误信息。

### 更新工作流定义

1. 获取目标工作流的 ID。
2. 调用 `PUT /admin/workflows/{id}` 接口，提交新的流程定义与名称。
3. 系统验证新定义合法性后更新流程。
4. 新定义仅影响未来新建的执行实例，不改变已有执行记录。

### 手动触发流程回滚

1. 确认某次流程执行失败且处于可回滚状态。
2. 调用 `RollbackService::rollback()` 方法，传入执行实例上下文。
3. 系统执行回滚逻辑，返回是否成功、回滚节点列表及可能的错误信息。
4. 回滚完成后，流程状态将被更新，可重新尝试执行。

## 相关配置说明

- **流程状态字段**：`status` 字段用于标识流程当前状态，如“启用”、“禁用”等，影响是否可被启动执行。
- **流程版本控制**：`version` 字段用于记录流程变更历史，建议每次更新时递增版本号。
- **租户隔离**：所有流程、执行实例及节点数据均按 `tenant_id` 进行隔离，确保多租户环境下的数据独立性。
- **流程定义存储**：`config` 字段存储完整的流程定义内容（JSON 格式），由系统内部解析使用，无需手动编辑。
- **节点顺序控制**：`order` 字段决定节点执行顺序，系统依据此字段组织流程推进路径。

> 注：本模块未提供前端页面路由，所有操作需通过 API 接口完成。相关功能可通过后台服务调用或集成至自研管理系统中实现。
